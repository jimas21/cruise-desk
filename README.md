# Deal Desk

A native iPhone app for the cruise deal desk: the deals Claude finds, one glance per deal, answered with a swipe.

- **Deals**: new deals with no answer yet. Each row answers four questions in one look: what (ship, nights,
  dates), where from, what it costs the family (one big number) and why it's good (one short line). Swipe right
  for Interested, left for Not for me or Later. Tap for the details, grouped into short labelled sections.
- **Reviewed**: answered deals by answer, with Claude's reply.
- **Save**: every way to save, live offers first with their deadlines, then standing tricks.
- **Rules**: Claude's suggested rules (Use / No), your rules (Pause), paused and declined ones, and what Claude
  looks for.

It reads and writes the `dealdesk-api` server described in the cruise-watch design notes: `GET /v1/sync` on launch
and on pull to refresh, cached on the phone so it opens instantly and works offline (answers made offline are sent
when the phone is back online), and versioned writes that re-sync and retry once when something changed at the same
time. Alerts arrive as native push; a tap opens that deal. `dealdesk://deal/<id>` links do the same.

## Building

No Mac is involved. Everything runs on GitHub Actions; the Xcode project is generated by XcodeGen from
`project.yml` and never committed.

| Workflow | Where | What it does |
| --- | --- | --- |
| `Compile check` | here | Unsigned simulator build on every push, then the unit tests (`Tests/`) on an iPhone simulator. It also renders every screen from sample data, light and dark, and uploads them as the run's `screenshots` artifact. No secrets. |
| `Deal Desk TestFlight` | the team's signing repository (copy of `ci/rogue-pocket/dealdesk-testflight.yml`) | Preflight, registers the bundle ID and turns on Push Notifications for it (`ci/asc_setup.py`), checks the App Store Connect app record, picks the build number, draws the icon (`ci/make_icon.py`), archives with the server address and app token from secrets, and uploads to TestFlight. |

Settings the TestFlight workflow needs (names only; values live in GitHub secrets): variable `TEAM_ID`, secrets
`ASC_KEY_ID`, `ASC_ISSUER_ID`, `ASC_KEY_P8`, `DEALDESK_BUNDLE_ID`, `DEALDESK_BASE_URL`, `DEALDESK_APP_TOKEN`, and
`DEALDESK_DEPLOY_KEY` (a read-only deploy key for this repository, only while it is private).

One-time steps only the account holder can do:

1. Create the App Store Connect app record for the bundle ID (the workflow stops and prints the exact steps if it
   is missing).
2. Create an APNs key (.p8) in the developer portal (Keys > + > Apple Push Notifications service) and give it to
   the deal server, which sends the alerts.

## Artwork

All original, no trademarks and no text. The app icon and the launch-screen mark are drawn at build time by
`ci/make_icon.py` (Pillow): a porthole looking out on a golden-hour sea with a small ship on the horizon. Inside the
app everything is vector SwiftUI (`App/UI/Art.swift`): the sea scene at the top of Deals (a night sky with moon and
stars in dark mode), the kind-tinted hero behind a deal's name, and the calm-sea pictures on empty screens. The waves
drift slowly and stand still under Reduce Motion; the art is hidden from VoiceOver.

## Settings on the phone

The build carries the server address and app token (Info.plist `DDBaseURL` / `DDAppToken`, injected by CI; the
repository holds only placeholders). The token is copied into the Keychain at launch. Settings can override either
one by pasting, for recovery, and test the connection.
